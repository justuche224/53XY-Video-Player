# 53XY — Changelog (archive)

> Append-only, newest first. One bullet per shipped feature. The most recent entries live in [HANDOFF.md §7](./HANDOFF.md#7-changelog); older ones are archived here. The status table in [HANDOFF.md §2](./HANDOFF.md#2-status-table--single-source-of-truth) is the canonical feature list.

- **Moments Phase 2 — Browse & play** — closes the loop from a saved moment back into playback. A fifth **Moments** tab sits between History and Settings: reverse-chronological, grouped by title, searchable across note text and title, with long-press multi-select for delete and share. Tapping a moment opens a detail screen — full frame, episode label, position, capture date, note — with Play from here, Edit note, Share frame, and Delete. `resolveMomentTarget` relinks a moment whose video moved by matching **both** filename and duration (within 1000ms) against the current library, not filename alone — a same-named but different cut sitting in another folder is not picked up — and heals the moment's stored id/uri once it finds the right file; a moment whose file is genuinely gone still renders, dimmed, with everything but playback. The player's resume effect now accepts a `startMs` route param: when set, it seeks there instead of the saved resume position and suppresses the resume snackbar (telling the user they were "resumed" somewhere they didn't ask for would be a lie, and the snackbar's Restart action would throw away the position they came for), then clears the param via `router.setParams` so a stale value can't leak into the next video on prev/next. Code-reviewed, **not yet device-verified** — nobody has run it on a device yet; it's JS-only, so a reload is enough. Checklist at the end of [moments-browse plan](./superpowers/plans/2026-09-08-moments-browse.md#device-verification-checklist-for-the-user). Spec/plan: [moments-design](./superpowers/specs/2026-09-08-moments-design.md), [moments-browse-plan](./superpowers/plans/2026-09-08-moments-browse.md).

- **Moments Phase 1.5 — Device fixes** — device verification found two defects, both wrong assumptions rather than coding slips. (1) Moments never reached shared storage: `MANAGE_EXTERNAL_STORAGE` is a *special access* appop that must be granted in system settings, and the dev build did not even declare it — `android/` is gitignored CNG and `expo run:android` reuses a stale one, so a permission added to `app.config.ts` on 2026-08-16 never reached a directory generated 2026-07-31 (EAS prebuilds fresh, so production had it and dev did not). The app now detects the fallback, prompts once, re-probes on focus, and migrates existing frames into shared storage, rewriting each row only after its file actually moved. (2) The note never pre-filled for **embedded** subtitles: the app's parser only handles external sidecar files, and expo-video exposes subtitle track selection but no cue text — so `patches/expo-video+56.1.4.patch` now also forwards ExoPlayer's `onCues` as a `subtitleCueChange` event, alongside the pre-existing `BufferedDataSource` HEVC fix. Also fixed: `openAllFilesAccessSettings` deep-linked to the *production* package (the Metro server evaluates `app.config.ts` with whatever `APP_VARIANT` it was started with, and the hardcoded fallback was the production id), sending users to the wrong twin's toggle; it now uses `expo-application`'s `Application.applicationId`. Review caught two Criticals in the first cut that would have made the whole fix a silent no-op — `Directory.uri` always appends a trailing slash so the shared-storage check could never be true, and every `moveSync` would have thrown on the same non-existent-destination permission trap. Device-verified: 14/14 frames migrated, all paths rewritten, no HEVC regression.

- **Moments Phase 1 — Capture & store** — a bookmark button, first in the player's top bar action row, captures the exact on-screen frame: the player's cached position (never `player.currentTime`, which throws after expo-video releases the shared object), a cleaned-up title/episode label reusing the grouping engine's `normalizeTitle`/`formatEpisodeLabel`, and a note seeded from whatever subtitle line is on screen. Rows live in a new `moments` table (migration v11) with **no foreign key to `videos`** — deliberately, since `deleteVideosByIds` runs on every scan that finds a file gone and a moment has to outlive its file, so it stores its own snapshot (title, episode label, filename, folder, video uri, duration) instead of joining live. Frames + a `moments.json` manifest are written to `/storage/emulated/0/53XY/Moments` behind a `.nomedia` (survives uninstall and Clear Data, invisible to the gallery), falling back to the app document directory when shared storage isn't writable. Required a native change: `FrameGrabber.grabFrame` gained an `exact?: boolean` option using `MediaMetadataRetriever.OPTION_CLOSEST` instead of `OPTION_CLOSEST_SYNC` — the old keyframe-snapping path can land on a completely different shot at a typical 5–10s GOP, which is fine for a poster thumbnail and wrong for a moment the user asked to save. Capture shows a confirmation snackbar with an **Edit** action opening a note sheet. **Not shipped in this phase:** no Moments browse screen, no way to view or play back a saved moment, no restore-from-manifest flow — those are Phases 2 and 3. Code-reviewed, **not yet device-verified** — this touches native Kotlin and needs a `npx expo run:android` rebuild; checklist at the end of the plan. Spec/plan: [moments-design](./superpowers/specs/2026-09-08-moments-design.md), [moments-plan](./superpowers/plans/2026-09-08-moments-capture.md).
